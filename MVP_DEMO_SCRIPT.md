# Dr. Jewelry — сценарий демонстрации MVP

> **Аудитория:** заказчик · **Формат:** PWA (GitHub Pages) + админ-режим (PIN)  
> **Дата подготовки:** перед показом · ~20–30 минут с вопросами

---

## Перед встречей (5 мин)

| Шаг | Действие |
|-----|----------|
| 1 | Открыть PWA: `https://<user>.github.io/dr.jewelery/` (или актуальный `gh-pages`) |
| 2 | **Сброс кэша SW:** `Ctrl+Shift+R` (Win) / `Cmd+Shift+R` (Mac) или DevTools → Application → *Unregister* `flutter_service_worker.js` → перезагрузка |
| 3 | Ширина браузера **≥ 960 px** — иначе десктоп-sidebar каталога скрыт |
| 4 | На Supabase должны быть накатаны миграции **020–024** (продажа, черновики, галерея, удаление, **возврат**) |
| 5 | Админ-PIN уже настроен на устройстве демо (First Claim) |

**Бэкенд:** единый контур — `CloudDatabaseService` + `SupabaseConfig` (боевой проект), без локального офлайн-каталога.

**Таймзона KPI:** «день продаж» = календарная дата **KST (UTC+9)**. В UI дефолт — `kstTodayIsoDate()` (UTC+9, **не** системная локаль устройства). На сервере `sold_date_kst` выставляется в RPC/триггерах через `Asia/Seoul`.

## Сценарий 1 — Расширенная фильтрация (десктоп)

**Цель:** показать скорость UI и серверный поиск по всей базе (~1400+ `active`).

1. Перейти в **Каталог** (главная витрина).
2. Слева — **панель «Фильтры»** (sidebar).
3. **Слайдеры цены (₩) и веса (г)** — двигать без лагов; список фильтруется **на клиенте** по уже загруженным строкам (60 FPS, без лишних RPC).
4. Выбрать **несколько категорий** (chips) → **«Применить»** — запрос уходит в Supabase (`getProductsAdvancedQuery`, `category` + `status=active`), пагинация **40** + infinite scroll.
5. В поле **SKU** ввести артикул, которого **нет** в первых 40 позициях → **Enter** или **«Применить»** — серверный `sku.ilike('%…%')` (не локальный поиск).
6. **«Сбросить»** — дефолтные слайдеры, первая страница активных товаров.

**Рефрен для заказчика:** «Тяжёлое — на Supabase, лёгкое — в памяти браузера.»

---

## Сценарий 2 — Приёмка черновиков

**Цель:** товар не портит KPI витрины, пока не принят.

1. Админ → **Приёмка черновиков** (`DraftIntakeScreen`).
2. Показать таблицу: **миниатюра**, SKU, металл, вес, размер, вставки.
3. (При необходимости) кратко: карточка создаётся как **`hidden`**, не видна гостю на витрине (`status=active` только после приёмки).
4. Загрузка **галереи** — RPC `admin_set_product_additional_images`, колонка **`text[]`** (не jsonb).
5. Кнопка **🗑️** — безвозвратное удаление (`delete_draft_product_by_sku`).

**Рефрен:** «Черновик — вне витрины и вне KPI, пока не нажали „Принять“.»

---

## Сценарий 3 — «Принять» и печать ценника

**Цель:** один клик на витрину + этикетка.

1. В строке черновика нажать **«Принять»** — диалог наименования + превью бирки.
2. После успеха: `stock_quantity = 1`, `status = active` (RPC).
3. Автоматически открывается **диалог печати**:
   - розничный ценник **30×20 mm** (браузер, iframe → системная печать);
   - превью термобирки **23×11,5 mm** (TSPL на native).
4. Отдельно показать **🖨️ «Печать»** в строке (повторная печать без повторной приёмки).

**Рефрен:** «На Web печатаем через диалог браузера — без установки драйвера принтера.»

---

## Сценарий 4 — Продажа и частичный возврат

**Цель:** честная выручка по KST и обратный путь на витрину.

### 4.1 Ручная продажа

1. Админ-дашборд → выбрать **активный** товар.
2. Кнопка **«Продано»** (🤝 / ручная фиксация) → RPC `mark_product_sold_manual`.
3. Товар **исчезает с витрины** (`sold`, `stock=0`), в `sales_history` — плюсовая строка (триггер / лог).

### 4.2 История продаж (KST)

1. Раздел **«История продаж»** (`SalesHistoryScreen`).
2. В шапке — **выручка за день (KST)** и выбор даты; список по `sold_date_kst`.
3. Убедиться, что продажа видна **в нужном календарном дне KST**, а не «вчера/завтра» из-за локали ноутбука.

### 4.3 Частичный возврат

1. В строке продажи — **«Возврат»** (`Icons.assignment_return_outlined`).
2. Подтвердить в диалоге.
3. RPC **`process_product_return_manual`**:
   - сторно: **отрицательная** `price_krw`, KPI дня уменьшается;
   - товар снова **`active`**, `stock_quantity = 1` на витрине.
4. В списке — красная сумма сторно; при необходимости открыть **аудит** (`raw_legacy_payload`).

**Рефрен:** «Возврат — не удаление истории, а бухгалтерское сторно + возврат SKU на полку.»

## Типовые риски на демо

| Риск | Что сделать |
|------|-------------|
| Старая сборка PWA | Hard refresh + unregister SW |
| RPC 404 / RLS | Проверить миграции 020–024 на Supabase |
| Возврат «already_returned» | Брать другую свежую продажу |
| Печать не открывается | Разрешить всплывающие окна; попробовать Chrome |
| Sidebar не виден | Расширить окно ≥ 960 px |

---

## Порядок показа (рекомендуемый)

1. Каталог + фильтры (wow-эффект скорости)  
2. Приёмка + печать  
3. Продажа → история KST → возврат  
4. (Опционально) повторный поиск SKU в каталоге после возврата
